# Native Books + New Relic observability

Native Books is a small SwiftUI and Jetpack Compose login/library sample backed by shared Kotlin Multiplatform business logic. Both native hosts use the New Relic Mobile SDK for monitoring and preserve a synchronous KMP tracing contract for repository operations.

## Project layout

```text
NativeBooksObservability
├── Packages/NativeObservability   Swift package backed by New Relic iOS
├── Packages/SharedKMP             generated SharedKit XCFramework package
├── iosApp                         SwiftUI host application
├── androidObservability           Android New Relic adapter
├── androidApp                     Compose host application
└── shared                         KMP business logic and tracer bridge
```

The native adapters keep active operations in thread-safe registries. A start call returns a W3C-shaped trace ID and span ID to KMP; the repository uses that context for its `traceparent` request header and ends the same operation in `finally`. The adapters map the operation to a New Relic custom interaction and emit a `NativeSpan` custom event containing the context IDs, status, duration, and caller attributes.

New Relic's mobile SDK does not expose OpenTelemetry span handles or a manual harvest/flush API. Context IDs used by the KMP propagation contract are therefore generated by the adapter and attached to New Relic custom data for correlation. Harvest scheduling remains owned by New Relic.

## Credentials

New Relic Mobile requires a platform-specific 40-character application token. It does not use an ingest/license key. Create a separate mobile app and token for iOS and Android in New Relic.

### iOS

Create `iosApp/Secrets.xcconfig` from
`iosApp/Secrets.xcconfig.example`:

```xcconfig
NEW_RELIC_APP_TOKEN = YOUR_IOS_MOBILE_APP_TOKEN
```

The file is required for the iOS app target and is gitignored. Xcode includes it through
`iosApp/Configuration/NewRelic.xcconfig`; do not put the token in the tracked base config.

The SwiftUI host starts New Relic from its `UIApplicationDelegate` launch callback before it configures the local observability provider. The dependency is New Relic iOS `7.7.6`, consumed through Swift Package Manager.

### Android

Create `androidApp/secrets.properties` from
`androidApp/secrets.properties.example`:

```properties
NEW_RELIC_APP_TOKEN=YOUR_ANDROID_MOBILE_APP_TOKEN
```

The file is optional and gitignored. You can alternatively provide `NEW_RELIC_APP_TOKEN`
through `~/.gradle/gradle.properties` or the environment. Without a token, completed
operations are written to Logcat.

The launch activity starts New Relic after the application has prepared its immutable configuration. The Android app applies the New Relic instrumentation plugin and uses New Relic Android `7.8.1`.

Both native startup paths explicitly enable New Relic's stable collection features before starting the agent: distributed tracing, network request/error events, crashes and handled errors, interactions, app lifecycle metrics, logs, HTTP error-body capture, and offline/background reporting. Android also explicitly enables analytics events, which New Relic requires for mobile distributed tracing. The SDK then injects its own distributed-tracing headers into supported real network requests.

Android also includes New Relic NDK agent `1.1.5` so native signals, C/C++ exceptions, and ANR reports can be captured. New Relic currently classifies the NDK agent as an incubating feature, so it should receive extra production testing.

The deliberately unsafe experimental networking/gesture flags, Swift interaction tracing (which New Relic warns can crash apps without additional dynamic-method setup), and FedRAMP collector routing are not enabled. Because logs and HTTP error bodies may contain user data, production builds should apply an application-specific redaction policy before release.

The production library and Explore/search repositories call the real Open Library search API, including pagination and load-more requests. Ktor uses its Darwin engine on iOS and OkHttp engine on Android, so these normal application requests are automatically captured by the corresponding New Relic mobile agent. There is no startup-only diagnostic request. To extend a trace across the server boundary, the downstream API must also run a New Relic APM agent in the same account with distributed tracing enabled; Open Library is external, so its mobile trace ends at the HTTP client span.

New Relic automatically attaches its reserved native `sessionId` to mobile custom
events. The same value is also copied to the non-reserved `service.session.id`
and `newrelic.session.id` aliases so application telemetry can be grouped with
native mobile requests, errors, logs, crashes, and session replays.

Both hosts also emit `MobileSessionState` events for launch, foreground/active,
inactive, and background transitions. These events carry connection type,
battery and charging state, orientation, thermal/power state, and available
memory where the platform exposes it. iOS emits a separate `MobileDeviceState`
event when connectivity changes. Use the **Mobile Session Explorer** dashboard's
`Session ID` selector to populate the end-to-end and lifecycle/device timelines.

To inspect the complete timeline for one New Relic mobile session, first copy a
`sessionId` from a mobile event and run:

```nrql
FROM MobileRequest, MobileRequestError, MobileHandledException, MobileCrash,
     NativeSpan, NativeSpanEvent, NativeLog
SELECT timestamp, eventType(), name, requestUrl, `trace.id`, `span.id`
WHERE sessionId = 'PASTE_SESSION_ID'
ORDER BY timestamp
LIMIT MAX
```

Custom telemetry can also be filtered with `service.session.id` or
`newrelic.session.id`; both contain the same native New Relic session ID.

## Build and test

Run the Swift package tests:

```bash
swift test --package-path Packages/NativeObservability
```

Run shared tests and build the Android debug app:

```bash
./gradlew :shared:testDebugUnitTest :androidApp:assembleDebug
```

Rebuild the checked-in KMP XCFramework after changing shared Kotlin:

```bash
./scripts/build-shared-kmp-package.sh
```

Build the iOS app without signing:

```bash
xcodebuild \
  -workspace iosApp/NativeBooks.xcworkspace \
  -scheme NativeBooks \
  -sdk iphonesimulator \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  CODE_SIGNING_ALLOWED=NO build
```

## Validate New Relic data

Sign in, load the library, open a book, and use the waveform button to create a test operation. With an app token configured, query custom data in New Relic:

```sql
FROM NativeSpan SELECT * SINCE 30 minutes ago
```

Useful fields include `name`, `trace.id`, `span.id`, `span.status`, `duration.ms`, `app.platform`, and the KMP repository attributes.
